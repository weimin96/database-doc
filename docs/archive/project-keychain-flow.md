# 项目优先 + PostgreSQL 凭据管理历史验证（已废弃）

> 这是上一轮 Keychain 方案的历史验收记录。该实现已按用户要求被**本地 AES-256-GCM 加密文件**替代，参见[当前本地加密方案](../local-encrypted-credentials.md)。应用当前不调用 Keychain；以下内容仅为历史记录。

2026-10-21。原有项目和用户连接的 `preferences.json`、`workspace.json` 不迁移、不删除。

## 改造

- 新启软件首先打开项目选择器；新项目需填写名称保存后才能进入工作台和数据库连接。
- 项目关联的是 `preferences.json` 中的数据库连接 UUID，而不是复制第二份数据库设置；通过这个关联恢复主机、端口、库名、用户名、SSL、已勾选的表和模板。用户主动切换项目会断开上一个数据库。
- 新增 macOS `security-framework` Keychain 机密读写：服务为 `com.database-doc.desktop.postgres`，账户名为连接 UUID；原来的非敏感连接设置继续写 JSON，数据库密码不写 JSON 或 AI 请求。连接成功并读取元数据后才存入钥匙串；选择不保存则删除对应钥匙串密码。
- 打开有关联连接的项目时尝试由 Rust 直接读取 Keychain 并连接 SQLx，不将已保存密码返回 WebView。首次升级的旧连接无钥匙串密码会打开预填信息的连接面板。
- macOS 若要求二次授权或读写 Keychain 阻塞，8 秒超时后打开数据库连接面板，不让“切换项目”无限加载。密码输入框仍保持空白，用户可以输入密码并重新保存。

## 端到端检查

- 真实 Mac Tauri QA app 新项目启动即弹出项目选择器；创建并保存“钥匙串自动连接验收项目”后直接进入数据库连接面板。
- 使用独立 Docker PostgreSQL 17、SCRAM 密码成功连接，元数据加载 1 张表；勾选保存连接与密码后，macOS 登录钥匙串中可查询到以测试连接 UUID 为账户的 generic password 项。
- 项目配置 JSON 中仅存在连接 UUID；`preferences.json` 只存非敏感连接字段，不含明文密码。
- 在开发测试的应用二次构建后重新打开已有项目，项目关联的地址/端口/库名/用户名/SSL 都正确恢复；Keychain 授权读取出现等待，加入 8 秒超时后成功回退到预填连接面板。**由于测试中的 unsigned 开发二进制经过重新编译，未声称 Keychain 自动连接在所有签名/授权情况下都已验证通过**。正式包需按本机 Keychain 授权情况验证。
- Clippy、前端/文档验证与独立 PostgreSQL 后端集成测试均通过。隔离的 Docker PG、QA 连接配置和钥匙串测试项已清理。

## 注意

生产使用时，macOS 首次读取钥匙串可能询问权限；选择允许后可继续自动连接。若最终要在更多 Mac 分发并长期稳定读取既有钥匙串条目，需使用有效稳定的 macOS 应用代码签名身份，而不能仅依赖持续变化的未签名调试构建。
