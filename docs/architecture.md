# Database Doc 架构选型

状态：2026-10-20 已完成首版代码、模板与本机专项验证；真实模型和 Word/WPS 验收仍待完成。实现范围与证据见 [验证记录](validation.md)。

## 产品边界

Database Doc 是一款 macOS 本地桌面软件：连接 PostgreSQL、选择 Schema 和数据表，并依照内置 Word 模板导出 `.docx` 数据库设计说明书。

第一版包含数据库文档导出，以及 AI 补充缺失的表注释和字段注释。AI 生成建议，用户审阅、编辑并勾选后，应用才写回 PostgreSQL；已有注释不覆盖。不查询业务表中的记录，不修改业务数据、表结构或约束。

不需要应用账号、独立服务端、内置数据库、ER 图编辑器、在线预览和多数据库适配。桌面应用直接请求用户配置的 AI API；不需要在本机运行 HTTP 服务。不引入自主执行 SQL 的 Agent、MCP 或通用数据库工具调用。

## 已有素材实测

- 初始结构检查时，工作目录只有 `中规院基于AI的城市设计助手数据库设计文档v0.1.docx`，没有源代码或 Git 仓库。
- DOCX 约 1.1 MB；89 个 Word 表格，其中版本记录 1 个、数据表清单 1 个、字段明细表 87 个；字段明细采用 8 列固定布局。
- 原文档包括封面、版本记录、引言、部署说明、数据表清单、逐表字段设计及安全性说明，并有页眉页脚、Word 域代码与插图。
- 原文档没有模板占位标记，且包含原项目名称、单位、数据库环境等固定内容，**不可直接复制旧文档再追加新表**。
- `word/document.xml` 解压后约 30 MB，需验证模板引擎对长文档的内存、耗时与版式行为。

## 选型决定

| 位置 | 方案 | 边界 |
| --- | --- | --- |
| 桌面壳 | Tauri 2 | macOS 原生文件对话框、打包、资源访问 |
| 界面 | React + TypeScript + Vite + Tailwind + shadcn/ui | 连接、Schema/表选择、注释建议审阅、文档参数、导出反馈 |
| 数据库 | Rust `sqlx` 的 PostgreSQL 驱动 | 元数据读取及限定的注释回写，仅开放类型化 Tauri Commands |
| AI 请求 | Rust HTTP 客户端 + 用户配置的 OpenAI 兼容接口 | API 地址、模型、密钥；只生成结构化注释建议，不执行模型 SQL |
| Word 引擎 | `docxtemplater` + `pizzip` | 对内置的 `.docx` 模板填入变量、重复列表及详细字段行 |
| 本地配置 | Tauri 应用配置目录 | 只保存非敏感连接配置、用户偏好 |
| 密码与 API 密钥 | 仅运行时内存 | 不落盘，不集成 Keychain |
| 输出 | 原生 Save Dialog + 文件写入 | 仅输出 `.docx`；避免覆盖模板源文件 |

不使用 Electron、Spring Boot、Python 运行时、Java 运行时及数据库迁移系统。`tauri-plugin-sql` 虽支持 PostgreSQL，但不直接向 WebView 暴露任意数据库查询能力；Rust 端统一执行限定元数据查询和注释写入。首版只实现一种 OpenAI 兼容请求协议，不为尚未使用的供应商建立 Provider/SPI。

## 单一执行链路

```text
React 桌面界面
    │ 连接信息、Schema/表的选择、文档参数
    ▼
Tauri Commands（Rust）
    ├─ PostgreSQL SQLx：连接 → 列 Schema → 批量获取表及字段元数据
    ├─ AI HTTP：限定结构信息 → 注释建议 → Rust 校验 → 用户审阅
    ├─ PostgreSQL SQLx：用户确认 → 重新核验 → 注释事务写入 → 回读
    │ 返回与 PostgreSQL 无关的结构化 DTO
    ▼
TypeScript 文档数据模型
    │ 合并用户选择及文档参数；保持选择顺序
    ▼
Docxtemplater + PizZip
    │ 基于派生的、受控的 Word 模板，循环生成表清单和明细
    ▼
DOCX 字节 → 有效性检查 → 原生文件保存对话框 → 本地文件
```

上述模型只有一个 PostgreSQL 元数据读取实现和一个 DOCX 渲染实现；暂不设置 Provider/SPI、后台任务队列及持久化任务表。耗时生成应离开 UI 主线程；Web Worker 的可用性须以实际 DOCX 验证，不应在未验证时承诺导出性能。

AI 与导出共用同一份元数据读取逻辑。注释建议是独立的运行时草稿；未写回的建议不混入 DOCX。写回后重新查询数据库，使用实际 COMMENT 导出，避免文档与数据库不一致。未配置 AI 时仍可独立完成文档导出。

## 数据模型

- `ConnectionOptions`：host、port、database、username、password（仅运行时）、sslmode。
- `SchemaInfo`：schema 名称。
- `TableInfo`：schema、table、类型、表注释；表的唯一标识使用 `(schema, table)`，不得仅使用表名。
- `ColumnInfo`：字段名、序号、`format_type`、是否主键、是否非空、默认表达式、字段注释。
- `DocumentOptions`：项目名称、建设单位、文档版本、编制日期、可选概述文本、选中表列表及顺序。
- `AiSettings`：API base URL、model；密钥仅在运行时内存中保存，不进入配置 JSON。
- `CommentSuggestion`：Rust 分配的目标 ID、建议文本或无法判断的原因。目标 ID 映射至本次选中对象，模型不得新增目标。
- `CommentDraft`：连接会话标识、数据库标识、Schema/表名、表 OID、可选字段名与 attnum、结构快照、原始 COMMENT、建议文本、用户编辑文本及勾选状态。Rust 保留权威快照；前端只提交草稿 ID 和用户编辑结果，不能自行声明原始状态。
- `CommentWriteResult`：逐表结果（已提交、冲突、失败、结果待核实、尚未执行），包含目标项和可诊断原因。草稿不跨连接复用，断开连接或重启应用后失效。

第一版仅允许普通表和分区表，跳过 `pg_catalog` 与 `information_schema` 等系统 Schema。默认不导出视图、物化视图、序列、索引详单和外键关系图，后续以实际需求扩展。

数据库元数据使用 `pg_catalog.pg_namespace`、`pg_class`、`pg_attribute`、`pg_description`、`pg_attrdef`、`pg_constraint` 等查询。数据类型使用 PostgreSQL 自身的 `format_type` 展示，避免应用层自己拼接 `varchar`、`numeric`、`timestamp` 等格式。主键根据约束获取，兼容联合主键；默认值通过 `pg_get_expr` 获取，支持标识列及生成列状态区分。查询参数化并批量获取选中表元数据，避免一张表发起多次查询。

## 内置 Word 模板改造

**将当前 Word 文档视为视觉母版，不直接作为运行时的动态模板。** 一次性生成精简、可维护的 `database-design.template.docx`：

1. 保留原文件不改动。派生模板继承需要的封面布局、字体、页边距、页眉页脚、标题和表格样式。
2. 去除旧项目固定名称、单位、达梦数据库环境、旧章节正文、87 张历史表数据和历史版本信息。
3. 将封面、项目说明、版本号和日期改为有限的、明确的字段占位符。
4. 表清单部分保留标题行和一行循环样例，以 `selectedTables` 生成列表。
5. 字段明细部分仅留 **一个** “表标题 + 表题注 + 8 列字段表” 原型，以嵌套循环生成每张选中表和它的字段。
6. 表名和字段的“名称”来源于 PostgreSQL COMMENT；缺少注释时显示原标识符或空值，不凭空编造中文名称。“备注说明”在没有独立数据源时留空，避免重复注释。
7. 保留正确的 Word 标题样式用于目录；表题注在导出时生成明确编号。自动目录的页码依赖 Word/WPS 更新域，需要单独验收，不承诺 JS 直接计算页码。

所有模板由应用内置并受控。不执行用户 DOCX 中的宏、脚本或任意 JavaScript 表达式。未来开放自定义模板前，需要定义标签白名单及验证机制。

## 交互设计

单窗口，以连接和选择工作区为主，不设置复杂路由：

1. **连接**：填写 PostgreSQL 的 host/port/database/user/password/SSL，测试连接；可选记住连接信息。
2. **选择与导出**：选择 Schema，加载并搜索表，单选/批量选择/全选筛选结果；编辑项目名称、文档版本及其他元数据；显示实际选中的表数和字段数；选择导出路径、生成 DOCX；成功后支持在 Finder 中显示。
3. **补全注释**：对选中表扫描缺失项，配置 AI 服务及可选业务背景，展示将发送的结构信息；生成后按表审阅原注释与建议，支持编辑、勾选、放弃。点击“写入数据库”时展示连接目标、Schema 及表/字段数量，确认后写回；显示逐表结果并刷新元数据。生成建议本身不触发写入。

选择状态由 `(schema, table)` 唯一确定；搜索与切换 Schema 不应偷偷清除用户已经勾选的表。未选表不允许生成空报告。错误必须明确区分连接失败、认证失败、权限不足、元数据读取失败、模板渲染失败和文件写入失败。

## AI 服务设置

API 地址或密钥变更后，通过 Rust 请求 `GET {baseUrl}/models` 获取模型列表。界面延迟合并连续输入，过期响应不能更新当前模型；支持手动刷新，失败显式提示，不回退硬编码模型。选择模型后可调用 `POST {baseUrl}/chat/completions` 发送“仅回复 OK”，验证真实推理响应，测试不携带数据库结构或业务数据。

数据库密码和 API 密钥仅保留在当前运行期间，不保存到本地配置；已移除 Keychain 命令、界面和依赖。历史版本已有的系统钥匙串条目不由新版本读取或自动删除。

## AI 注释补全

### 输入与建议边界

- “缺失”定义为 COMMENT 为 NULL、空字符串或仅含空白；已有非空注释作为上下文，不能成为写入目标。原始值按实际内容保留，用于写前比较。
- 默认只发送选中表的 Schema/表名、字段名、类型、主键和非空标记，以及已有注释。可选业务背景由用户填写。不发送连接地址、用户名、密码、业务记录、默认表达式或整份 DOCX。
- 外部 API 会收到上述结构信息；首次发送及 API 地址变更后，用户须确认发送范围。模型和 API 地址由用户配置；支持 HTTPS；经用户确认，私有 IP、链路本地 IP 及本机回环地址允许 HTTP，公网地址仍要求 HTTPS。AI 请求在 Rust 内执行，密钥不进入 WebView 持久化状态；不将凭据转发到重定向地址。
- 按表分批生成，单次携带该表字段以保留上下文；设定请求超时、输入体积及输出长度上限。超限时明确标记该表未生成，不能静默截断字段。展示已完成/失败表数，不伪造百分比。
- 表名、已有注释及业务背景均作为数据处理，不能授予模型任何工具权限。输出只接受目标 ID、中文注释建议或无法判断原因；拒绝未知/重复 ID、空建议、超长文本和格式错误。输出不完整时明确列出未生成项，不将其视为成功。
- 无法从结构确定的枚举含义、单位、业务规则不得编造，返回“无法判断”供用户补充背景。即使 JSON 校验通过，语义仍需用户审阅，不用模型自报置信度替代审核。
- 不依赖所有兼容服务都支持严格 JSON Schema 或工具调用；应用端校验是必需步骤。认证失败、限流、超时、模型不存在及非兼容响应分别呈现，不静默换模型、不自动无限重试。已成功的表建议保留，用户可重试失败表；取消生成后不再调度新请求，也不触发写回。

### 受限数据库回写

回写范围仅为用户确认的 `COMMENT ON TABLE` 和 `COMMENT ON COLUMN`。模型只提供文本，SQL 由 Rust 根据已核验目标生成；不接受来自模型或前端的任意 SQL。

1. Rust 校验草稿所属连接、数据库、选中表范围及勾选项；用户修改后的文本仍需经过非空、长度等校验。切换数据库、重新连接或修改建议后，旧确认不得复用。
2. 每张表使用一个短事务；模型请求与人工审阅均在事务之外完成。按固定顺序处理表，设置锁等待和语句超时；分区对象只锁定实际目标，不递归锁定全部分区。
3. 在同一事务中先对目标表取得 `SHARE UPDATE EXCLUSIVE` 锁，再用新查询核对对象身份、字段身份、结构快照及原始 COMMENT。任何目标被重建、改名、结构变化或注释被他人填写，整张表标记冲突并回滚，要求刷新后重新审阅。不能仅在事务外检查一次再写入。
4. 通过参数绑定调用 PostgreSQL `format`，分别以 `%I` 引用 Schema、表和字段标识符，以 `%L` 引用注释文本，再执行受控生成的 COMMENT。标识符不能用普通值占位符替代；禁止直接拼接模型文本。特殊名称、单引号、换行及反斜杠须有实库用例。
5. 同表中任一项失败则该表全部回滚；成功提交后回读实际注释。批次遇到冲突或失败停止后续写入，已提交表保留并明确列出，不能声称全批次原子成功。再次执行前刷新缺失项并重新确认。
6. 提交时连接中断或提交后回读失败，标记“结果待核实”，停止批次且不盲目重试。重新连接原数据库核对对象和注释后再决定后续操作；无法区分的结果仍保持待核实，不能误报失败或成功。取消写入时停止后续表，当前事务须明确报告提交、回滚或待核实，已提交结果不自动撤销。

PostgreSQL 的 COMMENT 会替换现有注释，因此“只补缺失”由应用锁内复核保证；写注释通常需要对象所有者或相应角色权限，SELECT 权限不足以完成回写。应用不自动提权，不要求用户提供超级用户账号。锁模式、权限及 COMMENT 行为参考 [PostgreSQL COMMENT](https://www.postgresql.org/docs/18/sql-comment.html) 与 [显式锁](https://www.postgresql.org/docs/18/explicit-locking.html)；安全引用参考 [format](https://www.postgresql.org/docs/18/functions-string.html#FUNCTIONS-STRING-FORMAT)。目标 PostgreSQL 版本仍须实库验证。

首版不提供覆盖已有注释、删除注释、任意 SQL 控制台、自动修改表结构或一键撤销。事务提交后的更正需重新审阅并通过数据库管理流程处理，不承诺自动回滚已提交批次。

## 安全与资源约束

- SQLx 只从 Rust 命令执行元数据查询和受限注释写入；禁止提供通用任意 SQL 执行接口或从数据库下载业务数据。
- 仅导出时使用元数据可见账户即可；回写需具备注释权限，权限不足时仍可生成建议及导出文档。设置连接超时、查询超时，关闭不再使用的连接池。
- 密码与 API 密钥不进入前端持久化状态、本地 JSON、异常日志、导出文档或文件名；不提供凭据持久化或 Keychain 集成。错误信息不能原样透出包含凭据的请求头或完整响应体。
- 导出的 DOCX 不上传第三方服务；只有用户确认的结构信息发送至所配置 AI 服务。应用不需要内置 HTTP 后台服务。
- 大文档生成期间 UI 可响应；真实反映阶段与错误，不显示虚构百分比。
- 文件保存应验证路径与导出内容，避免损坏的 DOCX 被标记为成功，并避免直接覆盖原始模板。

## 验收门槛与技术风险

开发时先做 **真实母版的 DOCX 引擎 PoC**，再铺开 UI：用 0/1/3/20 张模拟表生成 Word 文档，重点确认 `docxtemplater` 是否能完整重复“标题段落 + 题注 + 整张表”及字段行，并保留分页、表头重复、页眉页脚和标题目录行为。若 PoC 在此母版上失败，优先调整派生模板结构，不立即引入第二套文档引擎。

最小验收包括：PostgreSQL 实库连接、跨 Schema 同名表、联合主键、COMMENT 缺失、不同字段数据类型、默认值/自增列、100+ 表选择、中文长注释、空选择、鉴权失败、目标文件不可写、生成 DOCX 在 Word 与 WPS 中可打开，以及导出内容不包含旧项目信息。

首版已生成派生模板并验证 1/3/20 表动态生成及捆绑 LibreOffice 渲染，完成应用代码和专用 PostgreSQL 17 实库验证。当前模板包含封面、概述、表清单和字段明细，使用无编号语义标题；自动目录、题注编号与旧页眉页脚的保留尚未实现。Word/WPS 实际打开仍待验收。

### AI 专项验收与实施顺序

保留先验证 DOCX 模板的顺序。P0/P1 完成模板清理和 0/1/3/20 表生成验证；P2 完成 Tauri 与真实 PostgreSQL 元数据读取；随后独立验证“单表缺失扫描 → 真实 AI 建议 → 审阅 → 事务回写 → 回读 → DOCX 导出”，再扩展批量处理与完整 UI，最后完成 macOS 打包和 Word/WPS 验收。

实现时先在可丢弃 PostgreSQL 测试库验证受限写入，不以生产库作为首次试验对象：

| 验收场景 | 预期结果 |
| --- | --- |
| 表和字段均缺失、部分缺失、全部已有注释、仅空白注释 | 仅生成和写入缺失项；全部已有时不发起 AI 请求 |
| 用户编辑、未勾选、放弃或取消生成 | 只写入最终确认项；其他对象不变 |
| 跨 Schema 同名表、带特殊字符名称、分区表 | 仅影响准确匹配的对象；分区不隐式传播写入 |
| 注释含单引号、反斜杠、换行或 SQL 片段 | 内容作为文本保存，不执行额外语句 |
| 审阅期间他人补注释、改结构、删建表或字段 | 写前发现冲突；不覆盖新注释，不写入新对象 |
| 两个连接同时写同一缺失项 | 后获得锁的一方复核后报告冲突，不能覆盖先提交内容 |
| 权限不足、锁等待超时、同表第二项写入失败 | 当前表无部分提交；错误明确，后续表未执行 |
| 批次中断、提交时断线、提交后回读失败 | 区分已提交、回滚、待核实和未执行，不自动重放 |
| AI 超时、限流、返回非法 JSON、未知目标或不完整结果 | 明确标记失败/未生成项，无数据库写入；可单独重试 |
| AI 输入包含指令式已有注释、缺少业务含义 | 不执行工具或任意 SQL；无法确定的语义留待补充 |
| 远程 API、请求重定向、日志与本地配置检查 | 只发送确认范围；凭据不泄漏、不随重定向转发 |
| 写回成功后导出；未写回建议存在时导出 | 文档只使用重新读取的数据库注释，不使用草稿冒充 COMMENT |

自动化验证覆盖草稿校验、缺失判定、目标约束与错误分类；实库集成验证权限、引用、锁、竞态和事务。UI 通过人工操作验收，不编写 UI 单元测试。首版已提供代码和专项测试；上述标准中已有通过证据和仍待验证的项目分别列在 [验证记录](validation.md)。本机 AI 协议夹具只证明请求与处理链路，不代表真实模型语义质量。
